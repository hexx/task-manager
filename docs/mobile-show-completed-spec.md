# モバイルでの完了タスク表示 仕様（v3）

> ステータス: 確定（grill-with-docs セッション 2026-08-22 合意済み）
> 用語の定義は [CONTEXT.md](../CONTEXT.md) を参照。

## 改訂歴

- **v3（2026-08-22）**: 完了トグルのフィードバックを**楽観的更新**に変更（モバイル・デスクトップ共通）。トグル時の全件再取得とそれに伴う「Loading tasks…」の挿入を廃止し、タップ直後の即時反映と 1 回だけの行移動にする。完了した行が一覧から抜ける「並び」の挙動自体は現行維持（退場アニメーション等は追加しない）。
- **v2（2026-08-22）**: モバイルの導線を「ヘッダーのトグル」から「リスト末尾の開閉セクション」に置き換え。発見可能性の問題（ボタンがどこにあるか分からない）を解決する。
- v1（2026-08-10、確定・実装済み commit `9588cae`）: モバイルヘッダーにも「完了を表示」トグルを表示する仕様。要点は「`hidden md:inline-flex` を外し、モバイルでもトグルを常時表示」「表示状態はセッション内のみ」「デスクトップ不変」「CONTEXT.md への用語追加なし」。

## 1. 背景・目的

v1 の実装により、モバイル（`md` ブレイクポイント 768px 未満）でも「完了を表示」トグルから完了 Task を閲覧できるようになった。

しかし、このトグルはアイコンなし・グレーの小さい文字だけ（`variant="ghost" size="xs"`）のボタンとしてヘッダー右端に置かれ、タイトルや「N/M completed」に溶け込んで**発見できない**。実地のフィードバックとして「完了を表示ボタンがどこにあるのか分からない」が上がった。v2 はこの問題に対し、モバイルで完了 Task への導線を**「ボタンを探す」ことを前提としない形**、すなわち Task リスト最下部の常設の開閉セクションに置き換えた。

v2 の実装後、今度は別の不満が上がった: **完了チェックを押すと画面が 2 度にわたってずれ、連続でチェックしづらい**。原因はトグルの実装にある。

1. `toggleTask` は PATCH の後に `loadTasks()` を呼ぶが、`loadTasks()` は `loading` 状態を立てるため、リスト上に「Loading tasks…」が**挿入**されて画面が下へずれる
2. サーバー応答後に Loading 行が消え、さらに完了した行が一覧から消えるため、**もう一度**ずれる

加えて、PATCH 応答までチェック状態が一切変わらないため「押したのに反応がない → 突然 2 度ずれる」体験になっていた。本仕様 v3 は、トグルのフィードバックを楽観的更新にし、トグル時の全件再取得を廃止することでこの 2 度打ちのリフローを解消する。行が一覧から抜ける「並び」の挙動は変えず、フィードバックのタイミングと回数だけを直す。

## 2. 概念モデル

| 概念 | 説明 |
|---|---|
| **完了タスクセクション** | Task リストの末尾に常設された開閉領域。現在の絞り込み（すべて / Folder / 未分類）を**変えずに**、その中に含まれる完了 Task を一覧する。開閉は表示の操作であり、Task の状態は変更しない。 |

- 現在の絞り込み条件（Folder 選択）とは**直交**する表示要素。スコープを変えず、スコープ内の完了 Task の見え方だけを制御する
- 開閉状態は**セッション内のみ**保持し、リロードで閉じた状態に戻る
- CONTEXT.md への用語追加は**しない**（v3 で導入する楽観的更新も同様。Task の状態を変えない純粋な表示・通信の話であり、ドメイン概念ではないため）

## 3. 適用範囲

- **モバイル**（`md` 未満）: 完了タスクセクションの常設表示（v2）
- **デスクトップ**（`md` 以上）: ヘッダーの「完了を表示 / 完了を隠す」トグルと表示規則（`showCompleted` 駆動）は**現行どおり維持**する。ただし **v3 の楽観的更新（第 5 節）はデスクトップのトグルにも適用する**
- Checklist は対象外（ChecklistItem のチェック状態は常に一覧で見え、行が移動しないため）

## 4. 機能要件（モバイルの完了タスクセクション）

### 4.1 セクション行の表示

| 項目 | 仕様 |
|---|---|
| 位置 | Task リスト（`<ul>`）の直後、CardContent 内の最下部に常設 |
| 表示条件 | 現在の絞り込み内の完了 Task が **0 件のときは行自体を表示しない** |
| ラベル（閉） | 「完了したタスク **N** 件を表示」（N = 現在の絞り込み内の完了 Task 数。`completedCount` を流用） |
| ラベル（開） | 「完了したタスク **N** 件を隠す」 |
| アイコン | シェブロン（`ChevronDownIcon`）。開閉に連動して回転させる（フォルダ選択トリガーと同様の変更） |
| 挙動 | タップで開閉し、完了 Task の表示/非表示が即時反映される。`aria-expanded` を付与 |
| 表示ブレイクポイント | `md:hidden`（デスクトップでは表示しない） |

### 4.2 展開時の一覧

- 展開すると、現在の絞り込み内の完了 Task をセクション内に表示する（通常の Task 行コンポーネントを再利用）
- `line-through` など完了 Task の現行スタイルを維持する
- 行の並び順は、現行の一覧から未完了一覧を除いた順（既存の `visibleTasks` 相当を完了のみにした順）
- セクション内で可能な操作は、現行のトグル表示中と同一:
  - チェック外し（未完了に戻す）
  - Folder 移動（モバイルではボトムシート）
  - Deadline の編集
  - 削除
- 未完了に戻した Task はセクションから離れ、本体の一覧に即時反映される（N の表示も減る。第 5 節の楽観的更新により即時・1 回だけ動く）

### 4.3 モバイルヘッダーのトグル廃止

- ヘッダー右の「完了を表示 / 完了を隠す」ボタンはモバイルでは**表示しない**（v1 で外した `hidden md:inline-flex` を再付与する）
- `showCompleted` 状態はデスクトップ専用となり、モバイルではセクションの開閉 state に置き換わる
- ヘッダーの「{completedCount}/{totalCount} completed」、タイトル行、フォルダ選択トリガーは現行維持

### 4.4 空状態メッセージとの関係

- `No tasks yet.` / `All tasks completed.` は現行維持（変更しない）
- 全 Task 完了時は、`All tasks completed.` の直下に「完了したタスク N 件を表示」が見えるため、復元導線はこのセクション行に集約される

## 5. 完了トグルの即時フィードバック（楽観的更新、v3）

モバイル・デスクトップの**どちらの完了トグルにも**適用される。チェックを入れる操作（完了）と外す操作（チェック外し、完了セクション内を含む）を**対称に**扱う。

### 5.1 挙動

| 項目 | 仕様 |
|---|---|
| 即時反映 | タップした瞬間にチェック状態を**ローカル状態へ即時反映**する（サーバー応答を待たない） |
| 行の移動 | 完了した行は**即座に**未完了一覧から抜ける。並びの挙動は従来どおり（v2 の仕様そのもの）。退場アニメーションや FLIP は追加しない |
| 成功時の再取得 | PATCH 成功後は `loadTasks()` による全件再取得を**呼ばない**。応答で返る Task をローカル状態へマージするだけにする |
| Loading の排除 | 上記により、トグル操作中に「Loading tasks…」は**出現しない** |
| カウントの即時更新 | モバイルのセクション行「完了したタスク N 件」（表示時）、ヘッダーの「N/M completed」はローカル状態から導出され、即時更新される |
| チェック外し | 完了セクション内でチェックを外すと、行は即座にセクションから離れてメイン一覧へ移動する（N も即時減少） |

- 完了セクションが展開中の場合、完了させた Task はセクション末尾に即時追加される（マージの結果として）
- 「タップ → 何も起きない → Loading 出現 → 行消滅」という従来の 2 度打ちリフローの代わりに、「タップ → チェック表示 → 行が 1 回だけ動く」になる。連打時は同じ位置をタップし続ければ、次の行のチェックボックスがその位置へ滑り込んでくるため連続完了しやすい

### 5.2 連打と競合の扱い（保留ガード）

- **異なる Task への連続トグルはブロックしない**。PATCH は並行的に送信してよい
- **同一 Task の連続トグル**（チェック → すぐ取り消し等）は、その Task の PATCH が応答するまで**その Task のチェックボックスのみ無効化**する（Task 単位の保留ガード。他 Task には影響しない）
- 通常はトグルした行が即座に一覧から抜けるためガードは見えない。行がその場に残る場面（デスクトップの「完了を表示」中など）でのみ、ごく短時間効く

### 5.3 失敗時の扱い

- PATCH が失敗したら、その Task のトグルを**巻き戻し**（ローカル状態を操作前へ戻す）、既存の共通エラー表示（タイトル入力下の `FieldError` 領域）に「Failed to update task.」を出す
- 通信断・認証切れは従来どおり `api.request` 側のページリロード回復に委ねる（巻き戻しと同時にリロードされるケースが大半）

## 6. やらないこと（YAGNI）

### v2 から継続

- 開閉状態の永続化（localStorage 保存。リロードで閉じる現行方針を維持）
- ヘッダーの「N/M completed」の変更・日本語化
- 空状態メッセージの変更（日本語化を含む）
- FolderPickerSheet の件数バッジの変更。**件数は常に未完了 Task のみを数える**（`if (!task.completed)`）という現挙動を仕様として確定する
- デスクトップのヘッダー・トグルの変更
- モバイルのタスク行レイアウト改善（`issues/issue-202607281142-mobile-task-row-layout.md` で管理）
- モバイルでの Folder 作成導線の追加・変更

### v3 で追加

- **トグル以外の Task 操作**（作成・削除・移動・期限変更）の Loading ちらつきの解消（これらの操作は従来どおり `loadTasks()` 再取得と Loading 表示を維持する）
- 完了行の退場アニメーション・FLIP・スクロールアンカーの導入
- 楽観的更新の対象を Checklist / Twitter ビューへ広げること
- グローバルな通信中ロック（連打をブロックするような仕組み）

## 7. 検証方法

- **v3**: 375px 幅でトグル操作中に「Loading tasks…」が一切出現しないこと
- **v3**: タップ直後（サーバー応答前）にチェックが入り、行が即座に未完了一覧から抜けること
- **v3**: 同じ位置を連続タップして複数 Task を続けて完了できること（タップごとに次の行のチェックボックスが同位置へ来る）
- **v3**: 完了セクション展開中は、完了させた Task がセクション末尾へ即時追加され N が即時増えること
- **v3**: 完了セクション内でチェックを外すと行が即座にメイン一覧へ移動し N が減ること
- **v3**: PATCH 失敗時（DevTools のオフライン等）にチェックが元に戻り、エラー文言が表示されること
- **v3**: デスクトップで `showCompleted=false` でも同じ即時反映・即時行消滅になること。`showCompleted=true` では行がその場に残ったまま即時反映され、ごく短時間の保留ガードが機能すること
- 375px 幅（DevTools デバイスモード）でリスト末尾に「完了したタスク N 件を表示」が表示され、タップで完了 Task が展開/折りたたみされること
- 完了 Task が 0 件のときにセクション行が表示されないこと
- 全 Task 完了時に `All tasks completed.` の直下でセクション行から全完了 Task を閲覧できること
- 768px 以上でセクション行が現れず、デスクトップは現行のトグル・見た目が変わらないこと
- `npm test` / `npm run typecheck` / `npm run lint` が緑であること
