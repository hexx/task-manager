# モバイルのフォルダ選択UI（ボトムシート）仕様（v1）

> ステータス: 確定（grill-with-docs セッション 2026-07-28 合意済み）
> 用語の定義は [CONTEXT.md](../CONTEXT.md) を参照。

## 1. 背景・目的

スマホ画面での Folder 選択が使いにくい。現状のモバイル版は Folder を**横並びの小さなタブ**（`overflow-x-auto` + `shrink-0`）で表示しており、次の問題がある。

- Folder が増えると横に伸び、目的の Folder が画面外に流れて**一覧できない**
- タブが小さく（`text-xs`、高さ約20px）**指で押しにくい**
- 長い Folder 名が省略されず、横の伸びを助長する
- 各タブに削除ボタン（ゴミ箱）が**常時表示**されており、選択タップと誤爆しやすい
- 同じ概念に `All tasks` / `All` / `未分類` と**3種類のラベル**が混在している

本仕様は、横タブを廃止して**画面下から開く縦の一覧（ボトムシート）**に置き換え、「一覧できる・押しやすい・誤操作しない」選択体験にする。

## 2. 概念モデル

| 概念 | 説明 |
|---|---|
| **All** | Folder への所属に関係なく、すべての Task を表示する絞り込み条件。Folder そのものではない。UI 表記は「すべて」 |
| **Unclassified** | どの Folder にも属していない Task のこと、およびそれだけを一覧する絞り込み条件。Folder そのものではないが、現実に存在する所属先であり、移動先としても選べる。UI 表記は「未分類」 |
| **Folder** | Task を分類するための入れ物（[CONTEXT.md](../CONTEXT.md) 既存定義） |

- All と Unclassified は**特別な絞り込み条件**であり、Folder とは区別する。一覧上では Folder の上下に配置して視覚的にも分ける。
- Unclassified の一覧表示は**サーバー側が既にサポート済み**（`GET /api/tasks?folderId=` → `WHERE folder_id IS NULL`）。本仕様で初めて UI から利用する。
- UI ラベルは**日本語に統一**する（「すべて」「未分類」）。`All tasks` / `All` の表記は廃止する。

## 3. 適用範囲

- **モバイルのみ**（`md` ブレイクポイント未満）。デスクトップのサイドバーは変更しない。
- タスク一覧・タスク行の既存の挙動（追加・完了・削除・〆切・移動）は変更しない。

## 4. 機能要件

### 4.1 入り口（見出しボタン）

| 項目 | 仕様 |
|---|---|
| 位置 | タスクカードの見出し（現在「All tasks」または Folder 名を表示している箇所） |
| 形状 | 見出しテキストそのものをボタン化し、下向きの小さな三角印（chevron-down 系）を付ける |
| 表示内容 | 現在の選択内容（「すべて」または Folder 名） |
| 削除するもの | 見出し右の「フォルダ追加」アイコンボタン（モバイル用）。作成機能はシート内に移る |

### 4.2 シートの一覧

| 項目 | 仕様 |
|---|---|
| 並び順 | 「すべて」→ 各 Folder（作成順）→「未分類」 |
| 各行の内容 | Folder アイコン + 名前（1行に省略、`truncate`）+ 右側に**未完了の Task 件数** |
| 行の高さ | **最低44px**（指で押しやすいタップ領域の確保） |
| ゴミ箱ボタン | Folder の行にのみ表示。「すべて」「未分類」には付けない |
| 選択中の表示 | 現在選択中の行を目立たせる（背景色 + 太字など既存スタイルに準拠） |
| 開いたときの位置 | 選択中の行が画面内に入るよう**自動スクロール** |

件数の実装：Task をフィルターなしで一度全件取得し、クライアント側で Folder ごとに未完了件数を集計する（個人利用の規模を前提）。

### 4.3 選択の振る舞い

| 操作 | 仕様 |
|---|---|
| 行のタップ | 絞り込みを即適用し、**シートは閉じる** |
| 背景（バックドロップ）のタップ | 何も選ばずに閉じる |
| 下スワイプ | 何も選ばずに閉じる（OS標準的な挙動） |
| 選択の反映先 | 選択状態 `FolderSelection`（`all` ｜ `unclassified` ｜ `folder` + id）。Task は常に**フィルターなしで全件取得**し、選択ごとの絞り込みは**クライアント側**で行う（切り替えは追加通信なしで即座に反映される。件数集計もこの全件データから算出する） |

### 4.4 Folder の作成

| 項目 | 仕様 |
|---|---|
| 導線 | 一覧の**一番下**に「新しいフォルダ」行（プラスアイコン付き）を常時表示 |
| 操作 | タップすると行が入力欄に切り替わり、**自動でキーボードが開く**（autofocus） |
| 確定 | Enter キーまたは「作成」ボタン |
| バリデーション | 名前が空（空白のみも含む）の場合はエラーを表示し、作成しない（既存挙動に同じ） |
| 作成後 | シートは**開いたまま**。入力欄は空に戻り、新しい Folder は一覧の作成順の位置に表示される。**自動選択はしない**（連続作成を妨げないため） |

### 4.5 Folder の削除

| 項目 | 仕様 |
|---|---|
| 導線 | Folder 行のゴミ箱ボタン |
| 確認 | **必ず確認ダイアログを挟む**（現状の確認なし即削除を廃止） |
| 確認文（中に Task がある場合） | `フォルダ『{名前}』を削除しますか？中のタスク{N}件は『未分類』になります。` |
| 確認文（空の場合） | `フォルダ『{名前}』を削除しますか？` |
| ボタン | 「削除」（destructive / 赤系）と「キャンセル」 |
| 削除後 | シートは**開いたまま**。削除された Folder は一覧から即座に消える |
| 選択中の Folder を削除した場合 | 表示は「すべて」に切り替わる（既存挙動に同じ） |
| タスクの扱い | 削除しない。サーバー側で `folderId` が `null` になり、「未分類」に移動する（既存挙動。確認文で利用者にも明示する） |

### 4.6 v1 でやらないこと（YAGNI）

- Folder の**名前変更**（API は `PATCH /api/folders/:id` で対応済みだが、デスクトップ含め UI 未実装。本仕様の課題「選びにくい」の範囲外）
- 作成直後の**自動選択**
- 選択中 Folder の**再読み込み後の記憶**（現状どおり「すべて」に戻る）
- デスクトップのサイドバー変更（ゴミ箱の確認なし削除を含む）
- モバイルのタスク行の窮屈さ（日付入力・移動先 select・削除ボタンの横並び）
- Unclassified 行へのゴミ箱（概念上存在し得ない）
