# 課題解決プロンプト: Cloudflare Access認証下でのCORS/リダイレクトエラー修正

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび問題解決のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**: アプリケーションがCloudflare Access (Zero Trust) でドメイン全体が保護されている状態で、フロントエンドからバックエンドAPI(`/api/*`)にリクエストを送信する際、FetchリクエストにセッションCookie (`CF_Authorization`) が含まれないため、Cloudflare Accessが未認証と判断し、ログイン画面へリダイレクトさせようとしています。その結果、フロントエンドでCORSエラーおよび `FetchEvent resulted in a network error` が発生し、アプリがクラッシュしています。
- **再現手順**: Cloudflare Accessで保護されたドメインで、フロントエンドから `/api/*` エンドポイントにFetchリクエストを送信する。認証Cookieが送信されないため、CORSエラーが発生する。
- **関連ファイル/コード**: `src/client/api.ts` 内の `request` 関数（`fetch` のラッパー）

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `fetch` のオプションに `credentials: 'include'` を追加し、Cloudflare Accessの認証Cookie (`CF_Authorization`) がAPIリクエスト時に必ず送信されるようにする
- [ ] `fetch` がネットワークエラー（`TypeError: Failed to fetch` 等）で失敗した場合、またはステータスコードによってCloudflareのログインページが返されたと推測される場合は、`window.location.reload()` を呼び出してページ全体をリロードするエラーハンドリングを追加する
- [ ] 既存の型定義やその他のAPIメソッド（`folderApi`, `taskApi`）のシグネチャは変更しない
- [ ] エラーハンドリングは無限ループのリロードが発生しないよう注意して実装する

## 4. 期待する成果物 (Output Format)
- 修正が完了した `src/client/api.ts` のコード一式、または修正パッチ
- 修正理由とアプローチの簡潔な解説
- 動作確認またはテストの実行結果
