# 課題解決プロンプト: Cloudflare Access環境下でのPWA Service Workerキャッシュ戦略修正

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび問題解決のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**: `task-manager` アプリで、Cloudflare Access環境下においてPWAのService Worker（Workbox）が悪影響を及ぼしています。デフォルトのキャッシュ戦略により、Cloudflare Accessのセッションが切れた状態でもブラウザはキャッシュされたアプリ画面を表示してしまい、その後のAPIリクエスト（`/api/*`）がCloudflareに弾かれてCORSエラーが発生しています。
- **再現手順**: 
  1. Cloudflare Accessで保護された環境で`task-manager`アプリにアクセス
  2. セッションを切らす（またはCloudflare Accessのセッションが自然に切れるのを待つ）
  3. ブラウザでページを更新または新しい画面に遷移
  4. キャッシュされたアプリ画面が表示され、APIリクエストがCORSエラーになることを確認
- **関連ファイル/コード**: `vite.config.ts`（VitePWAプラグインのWorkbox設定）

## 3. 解決すべきゴール (Goal & Objective)
- [ ] SPAフォールバックの無効化: Workboxがナビゲーションリクエストに対して強制的にキャッシュされた`index.html`を返すのを防ぐため、`workbox`オプション内に`navigateFallback: null`を追加
- [ ] HTMLのキャッシュ戦略変更: ナビゲーションリクエスト（画面遷移時のHTML取得）に対して`NetworkFirst`戦略を適用する`runtimeCaching`ルールを追加
  - `urlPattern: ({ request }) => request.mode === 'navigate'`
  - `handler: 'NetworkFirst'`
  - `options.cacheName: 'pages-cache'`
- [ ] プリキャッシュからの除外: `globPatterns`から`html`を除外し、`['**/*.{js,css,svg,png,woff2}']`に変更
- [ ] 既存の機能を壊さず、オフライン時にもキャッシュされた画面が表示可能であること

## 4. 期待する成果物 (Output Format)
- `vite.config.ts`の修正コード一式
- 修正理由とアプローチの簡潔な解説
- 動作確認手順またはテストの実行結果
